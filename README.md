# Used Car Price Prediction with a Neural Network (ANN)

**Methods practised:** artificial neural networks for regression — layers, ReLU, loss, scaling, early stopping
(Batch 2 Module 05); TensorFlow/Keras functional API, `EarlyStopping`, training curves, saving `.keras` models
(Module 06); and an honest comparison with classical models — Ridge and gradient boosting (Module 03).

## Problem statement

A used-car marketplace in India wants to show an **instant price estimate** while a seller fills in a listing.
Given the brand, body type, year, kilometres, fuel, gearbox, number of owners, city, seller type, mileage and engine
size, predict the selling price in **lakh rupees**.

**Expected result:** a neural network that beats a "predict the average price" baseline by a wide margin, compared
fairly with gradient boosting (on tabular data like this, boosted trees often match or beat neural networks), served
through an API and a web form that shows both estimates side by side. The build run's actual numbers are in
`VERIFICATION.md` and the executed notebook.

## Dataset

Synthetic listings generated by `data/generate_data.py` (seed 42): 6,000 cars from 9 brands in 8 cities, built from
2010 to 2024. Prices follow a realistic depreciation formula (value falls by a fixed share every year, more km and more
owners lower it, SUVs/automatics/dealers raise it, old diesels sell cheaply in Delhi) plus about ±9% noise.
The file is deliberately messy: 80 duplicate listings, missing values, "Bangalore" next to "Bengaluru", and 12
impossible odometer readings. Electric cars have empty mileage and engine size because those do not apply to them.
See [data/DATA_DICTIONARY.md](data/DATA_DICTIONARY.md). The target column is `price_lakhs`.

## What the notebook does

1. Load and inspect; find duplicates, the two spellings of Bengaluru, impossible km values, and which missing values
   are "not applicable" (electric) vs really missing.
2. Clean, then create `car_age = 2025 − year`.
3. Explore with plots: price distribution (and its log), price vs age/km/brand/fuel, correlations.
4. One preprocessing pipeline for all models: median impute + missing-indicator + standard scaling for numbers,
   most-frequent impute + one-hot for categories.
5. **Experiment:** predict price or `log(1 + price)`? (cross-validated, for Ridge, gradient boosting and the MLP).
6. Train the baseline, Ridge, `HistGradientBoostingRegressor` and an `MLPRegressor` ANN with early stopping; report MAE
   in lakhs, MAPE and R²; plot the ANN's training curves; 5-fold cross-validation.
7. Keras functional ANN on the same preprocessed inputs, with `EarlyStopping`, training curves and `.keras` saving
   (cells marked `# NO-RUN`: they need TensorFlow — see below).
8. Error analysis by segment and fuel, new example listings and edge cases, save and reload all artifacts, limitations.

## How to run (three terminals)

**1. Python environment and notebook** (from this project folder):

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
jupyter notebook notebook/Used_Car_Price_ANN.ipynb     # Run All: this creates models/
```

The trained scikit-learn models are already included in `models/`, so you can skip straight to step 2 if you only
want the app.

*Optional — the Keras part.* Use Python 3.10–3.12, then:

```bash
pip install -r requirements-tf.txt
```

and run the cells that start with `# NO-RUN` (Jupyter runs them normally; the marker only told the course build to skip
them). The last one writes `models/car_price_ann.keras`. From then on the API uses the Keras model automatically.

**2. Backend API** (same environment, from this project folder):

```bash
python backend/app.py                 # http://localhost:5000
python -m unittest discover -s backend -p "test_*.py" -v    # optional: run the tests
```

At start-up the API prints which neural network it uses. Without TensorFlow or without `car_price_ann.keras` it says so
and uses the scikit-learn MLP. Force the scikit-learn model with `CAR_MODEL=sklearn python backend/app.py`.

Try it without the frontend:

```bash
curl http://localhost:5000/api/health
curl -X POST http://localhost:5000/api/predict -H "Content-Type: application/json" \
  -d '{"brand":"Maruti","model_segment":"Hatchback","year":2020,"km_driven":45000,"fuel":"Petrol","transmission":"Manual","owners":1,"city":"Pune","seller_type":"Individual","mileage_kmpl":21,"engine_cc":1200}'

# an electric car: leave mileage and engine size out
curl -X POST http://localhost:5000/api/predict -H "Content-Type: application/json" \
  -d '{"brand":"Tata","model_segment":"SUV","year":2023,"km_driven":25000,"fuel":"Electric","transmission":"Automatic","owners":1,"city":"Bengaluru","seller_type":"Individual"}'
```

**3. Frontend** (needs Node.js 18+):

```bash
cd frontend
npm install
npm run dev                           # open http://localhost:5173
```

If the API runs somewhere else, copy `.env.example` to `.env` and change `VITE_API_URL`. If the frontend runs on a
different address, start the backend with `FRONTEND_ORIGIN=http://that-address python backend/app.py`.

## Architecture and request flow

```
 Browser (React form)                 Flask API (backend/app.py)                        models/
 ───────────────────                  ──────────────────────────                        ───────
                                      at start-up, ONCE:
                                        Keras file + TensorFlow? ── yes ─▶ load ◀────── car_price_ann.keras
                                                                                 ◀────── preprocessor.joblib
                                                                 └─ no ──▶ load ◀────── car_price_mlp_sklearn.joblib
                                        load gradient boosting               ◀────── car_price_gb.joblib
                                        load allowed values / ranges         ◀────── model_info.json
 page opens ── GET /api/options ───▶  brands, cities, ranges
            ◀───────────────────────
 user submits ─ POST /api/predict ─▶  1. parse JSON (400 if not JSON)
   {brand, year, km_driven, ...}      2. validate every field (422 + per-field messages)
                                         year → car_age;  Electric → mileage/engine = missing
                                      3. one-row DataFrame → ANN predict  and  boosting predict
            ◀── 200 {predicted_price_lakhs, likely_range_lakhs, model,
                     comparison: {model, predicted_price_lakhs}, difference_pct, note}
 shows both estimates side by side, or the error next to the right field
```

- Models are **trained once in the notebook** and loaded **once when the API starts**. Requests only call `predict`.
- The scikit-learn files contain the **whole pipeline** (preprocessing + model + log/exp of the target), so the API sends
  raw values and gets lakhs back. The Keras model uses the saved `preprocessor.joblib` and `expm1` in the API.
- The likely range is *prediction ± the ANN's test MAPE (percent)*: errors grow with the price, so a percentage range is
  more honest than a fixed number of lakhs.

### API reference

| Method | Path | Request | Success response | Errors |
|---|---|---|---|---|
| GET | `/api/health` | — | `{"status": "ok", "ann_model": "...", "comparison_model": "...", "using_fallback": true}` | — |
| GET | `/api/options` | — | `{"categories": {...}, "numeric_ranges": {...}, "electric_min_year": n, "ann_model", "comparison_model", "test_metrics"}` | — |
| POST | `/api/predict` | JSON with the 11 listing fields | `{"predicted_price_lakhs": n, "likely_range_lakhs": [lo, hi], "model": "...", "comparison": {"model", "predicted_price_lakhs"}, "difference_pct": n, "note": "..."}` | 400 body not JSON; 422 `{"error", "fields": {field: message}}` |

Validation rules:
- `brand`, `model_segment`, `fuel`, `transmission`, `city`, `seller_type` are required and must be values the model has
  seen (`/api/options`). "Bangalore" is accepted and treated as "Bengaluru".
- `year`, `km_driven`, `owners` are required and must lie inside the training ranges; `year` and `owners` must be whole
  numbers.
- `mileage_kmpl` is required **unless fuel is Electric**; `engine_cc` is optional (filled with the training median).
- For Electric cars, `mileage_kmpl` and `engine_cc` must be empty, and the year must not be earlier than the first
  electric car in the data.

## Ideas to extend

- Rebuild the Keras model with `layers.Normalization` and `layers.StringLookup` inside the network, so the `.keras`
  file needs no scikit-learn preprocessor.
- Use **embeddings** for `brand` and `city` in Keras and compare with one-hot encoding.
- Tune the MLP (`hidden_layer_sizes`, `alpha`, `learning_rate_init`) with `RandomizedSearchCV`.
- Add a `km_per_year` feature and see whether the ANN or the boosting model benefits more.
- Predict a 10th–90th percentile range with `HistGradientBoostingRegressor(loss="quantile")` instead of ± MAPE.
- Log each request and show the most frequently priced brands on a small dashboard.
